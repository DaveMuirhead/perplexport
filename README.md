# Perplexity Account Exporter

Back up a Perplexity account to local Markdown, JSON and PDF — conversations, the files
attached to and generated by them, and the account context the assistant relies on
(stored memories and the Brain knowledge store).

The first run exports everything available. Later runs are incremental: unchanged
threads are skipped, new ones picked up, changed ones refreshed. That makes it suitable
for scheduled backups, not just a one-off export.

## What gets exported

| | Flag | What it covers |
|---|---|---|
| Conversations | *(default)* | Every thread in the library and in Spaces, as Markdown + JSON |
| Thread files | `--files` | Uploaded context files and generated results (PDF/XLSX/DOCX/MD/…) |
| Memories | `--memories` | The personalization facts at `/account/personalize/memories` |
| Brain | `--brain` | The knowledge store at `/computer/memory` — cross-linked notes about recurring people, projects and concepts |
| PDFs | `npm run pdf` | A `.pdf` beside each conversation |
| Manifest | *(always)* | `_manifest.md` — when the export ran, which account and organization, which flags, and how much was captured |

Citations inside a thread are resolved against whatever you exported: a cited Brain note
links to its local file, a cited memory is quoted inline, an earlier session links to
that conversation, and a cited attachment links to the downloaded copy. Anything not
exported keeps a plain label rather than becoming a broken link.

## Output

```
conversations/
  _manifest.md         ← when the export ran, which account, what it covered
  _manifest.json
  <uuid>.md            ← conversation, prompts and answers labelled
  <uuid>.json          ← raw thread data
  <uuid>.pdf           ← only with npm run pdf
  Space Name/
    _space.md          ← space title + instructions + thread list
    <uuid>.md / .json
  _memories.md         ← only with --memories
  _memories.json
  _brain/              ← only with --brain
    _index.md
    concepts/ entities/ projects/   ← one .md per note
    _brain.json
  _files/              ← only with --files
    <uuid>/
      manifest.json    ← what was found, sizes, sha256, status
      Report.pdf …
done.json              ← progress log; safe to resume after interruption
```

## Prerequisites

- **Node.js and npm** — [nodejs.org](https://nodejs.org)
- **Puppeteer Chrome** — if Chrome is missing: `npx puppeteer browsers install chrome`
- **Chrome system libraries** (Linux only) — minimal systems may need:
  ```bash
  sudo apt-get install -y libglib2.0-0 libnss3 libatk1.0-0 libatk-bridge2.0-0 \
    libxcomposite1 libxdamage1 libxfixes3 libxrandr2 libgbm1 libxkbcommon0 libasound2
  ```
  On macOS and Windows, no extra steps are needed.

## Install & run

```bash
git clone https://github.com/DaveMuirhead/perplexport.git
cd perplexport
npm install && npm run build
```

**Full backup** — everything, incremental on later runs:

```bash
node dist/cli.js --files --memories --brain
```

**Routine sync** — no flags, no login. Uses the saved 30-day session, runs headless, and
exports only new or changed threads:

```bash
node dist/cli.js
```

**First run / expired session** — pass your email to log in once:

```bash
node dist/cli.js -e your@email.com
```

Enter the 6-digit code sent to your email (**valid ~5 minutes**). The session is saved to
`session-cookies.json` and lasts ~30 days; during that time the routine sync works
without `-e`.

### Thread files

`--files` saves both the documents you uploaded as context and the files the assistant
generated, to `conversations/_files/<thread-uuid>/`, with a `manifest.json` recording
each file's kind (`upload` or `generated`), size, sha256 and status. Re-running skips
files already on disk, so it is safe to add to an existing export; `--refetch-files`
forces a re-download.

Two caveats, both upstream behaviour rather than tool limitations:

- Perplexity **prunes uploaded files** after a while. For older threads the upload is
  gone server-side and is recorded as `gone` in the manifest. Generated results are
  retained and still download fine.
- A file downloads only if it is still reachable at export time, so attachments are best
  captured by syncing regularly rather than years later.

### Memories and Brain

These are two separate stores, and neither is part of any conversation:

- `--memories` saves the short personalization facts Perplexity keeps about the account.
- `--brain` saves the long-form, cross-linked notes behind `/computer/memory`, one
  Markdown file per item under `concepts/`, `entities/`, `projects/`.

Threads cite both as sources with no link, because the content is held only server-side —
the assistant reads it inside its own sandbox and that output is stripped from exported
transcripts. Exporting them is the only way to resolve those citations.

### The manifest

Every run writes `_manifest.md` (and `_manifest.json`) to the output directory, so a
backup says what it is rather than being an unattributable folder of UUIDs:

```markdown
# Perplexity export

Exported **2026-10-21T02:42:40.097Z** by perplexport v2.1.0.

## Account
- **Username:** dave
- **Subscription:** pro
- **Org role:** ADMIN

## Organization
- **Name:** Acme
- **Created:** 2026-08-06
- **Thread retention:** unlimited

## Contents
- **Conversations:** 55
- **Spaces:** 1
- **Files downloaded:** 143
- **Files no longer stored upstream:** 88
- **Memories:** 21
- **Brain items:** 10

## Options
`--files`, `--memories`, `--brain`
```

(Email and the account/organization UUIDs are recorded too; they are elided here.)

Two fields are there to explain *gaps* rather than to describe the account:

- **Thread retention** — where an org admin has set one, older threads are deleted
  server-side. Recording it means a short history reads as policy rather than as a
  tool failure.
- **Warnings** — anything the run could not capture is listed, so a partial export is
  distinguishable from a complete one long after the logs have scrolled away.

### PDFs

`npm run pdf` renders each conversation to a `.pdf` beside its `.md`, using the Puppeteer
Chrome this project already requires (no pandoc or LaTeX):

```bash
npm run pdf                  # incremental — only new or changed conversations
npm run pdf -- --force       # rebuild every PDF
npm run pdf -- --only <uuid> # a single conversation
```

Output is a real text layer, not page images, so the PDFs stay searchable.

### Two-factor accounts (TOTP)

If your account has an authenticator-app second factor, the login flow asks for the TOTP
code after the email code. That page is protected by **Cloudflare Turnstile, which blocks
headless Chrome** — so on a server you must run the login headful under a virtual display:

```bash
xvfb-run -a node dist/cli.js -e your@email.com --headful
```

Accounts without 2FA don't need `--headful`. Once the session is saved, routine syncs work
headless again.

### Non-interactive / automated login

`--otp-fifo <path>` reads each code from a named pipe instead of prompting, so a script or
agent can deliver codes mid-run:

```bash
mkfifo /tmp/otp
xvfb-run -a node dist/cli.js -e your@email.com --headful --otp-fifo /tmp/otp &
echo 123456 > /tmp/otp
```

The emailed code wait times out after 5 minutes; the TOTP wait does not.

## Options

| Flag | Default | Description |
|------|---------|-------------|
| `--files` | off | Download uploaded context files and generated results |
| `--refetch-files` | off | With `--files`, re-download files that already exist on disk |
| `--memories` | off | Export the account's stored personalization memories |
| `--brain` | off | Export the Brain knowledge store (`/computer/memory`) |
| `--allow-incomplete` | off | Exit 0 even when the export is known to be incomplete (default: exit 2) |
| `-e` | only when cookies are missing or invalid | Perplexity account email |
| `-o` | `./conversations` | Output directory |
| `-c` | `session-cookies.json` | Session file |
| `-d` | `done.json` | Progress file |
| `--backup` | off | Rename existing output dir to `.backup` before running |
| `--headful` | off | Run a visible browser (use with `xvfb-run`) — needed for Cloudflare on the 2FA page |
| `--otp-fifo <path>` | off | Read the email/TOTP codes from a named pipe instead of prompting |

## Why a real browser?

Perplexity's REST API sits behind **Cloudflare bot management**, and a valid session cookie
isn't enough on its own: Cloudflare binds its `cf_clearance` cookie to the **TLS/JA3
fingerprint** of the browser that earned it. A plain Node `fetch` carrying the *exact same*
cookies gets a `403 "Just a moment…"` challenge.

So every `/rest/` call is issued from inside the Puppeteer page (`page.evaluate(() =>
fetch(...))`). The browser is the Cloudflare-passing client, not an HTML renderer — the data
itself is plain JSON. File downloads are the exception: those URLs are pre-signed and served
from S3/CloudFront, outside Cloudflare, so they use plain Node `fetch`.

## How the thread list is fetched (and when it can break)

`/rest/thread/list_recent` is **hard-capped at 20 threads** and ignores `limit`, `offset`,
`cursor`, `page` and `before` — so it cannot enumerate a library of any size. The full list
comes from the same GraphQL endpoint the Library page uses, which pages properly.

That endpoint takes *persisted* queries: the query text lives server-side and the client
references it by `sha256Hash`. **Those hashes are tied to a Perplexity frontend build and
will eventually change.** The same is true of the Brain query. When a hash rotates:

- the export does **not** fail — the library listing falls back to `list_recent`, and
  `--brain` reports that its hash needs refreshing
- but the fallback only sees the **20 most recent threads**, so the export becomes incomplete
- warnings are printed, naming the constant to update

```
  LibraryItemsRelayQuery: persisted query not recognised by the server (hash needs refreshing)
  Falling back to list_recent — only the 20 most recent threads.
  See LIBRARY_FIRST_PAGE_QUERY in src/config.ts for how to refresh.
```

**An incomplete export exits with status 2** and prints a banner to stderr, so a cron job
fails loudly instead of recording a partial backup as a success:

```
========================================================================
INCOMPLETE EXPORT — this backup does not cover the whole account
========================================================================

  [library-listing-fallback] The GraphQL library listing is unavailable, so
  only the 20 most recent threads could be listed. Older conversations were
  NOT exported.
  Fix: Refresh LIBRARY_FIRST_PAGE_QUERY / LIBRARY_NEXT_PAGE_QUERY in src/config.ts
```

Pass `--allow-incomplete` to exit 0 anyway. The same degradations are recorded under
Warnings in `_manifest.md`, so a partial backup is identifiable after the fact.

To refresh: open [perplexity.ai/library](https://www.perplexity.ai/library) (or
`/computer/memory` for Brain), scroll to load a second page, and copy `operationName` and
`extensions.persistedQuery.sha256Hash` from the `POST /rest/perplexity_ask/graphql` requests
into [src/config.ts](src/config.ts).

## Notes

- Incremental sync: re-running skips unchanged threads, picks up new ones, refreshes changed ones
- Main library chats are checked with a lightweight latest-entry request before any full re-export
- Space chats are checked via remote `last_query_datetime`
- Crash-safe: each file written atomically; progress saved after every thread
- **Not exported:** files attached to a *Space* itself rather than to a thread — that API
  endpoint has not been discovered yet (`list_collection_files` and variants all 404, though
  `list_user_collections` does expose a `file_count`)
- If Chrome doesn't launch: `npx puppeteer browsers install chrome`
